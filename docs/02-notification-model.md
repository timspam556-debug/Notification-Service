# Этап 2. Модель уведомления

Notification — класс, представляющий одно уведомление. Его экземпляр хранит адрес,
тему, текст, канал, состояние и количество начатых попыток. NotificationStatus и
NotificationChannel — enum: наборы именованных значений.

Свойства с get доступны для чтения. private set разрешает изменение только внутри
класса. Это инкапсуляция: вызывающий код не может произвольно присвоить Status = Sent.

Конструктор проверяет обязательные данные, email, ограничения длины и количество
попыток, затем создаёт уведомление в Pending. В HTTP-компоненте добавим DTO:
отдельный тип входного запроса, чтобы клиент не мог задавать внутреннее состояние.
Проверка email здесь синтаксическая и не подтверждает существование почтового ящика.

## Переходы

| Метод | Исходное состояние | Результат |
| --- | --- | --- |
| MarkQueued | Pending | Queued |
| BeginAttempt | Queued | Processing, AttemptsCount + 1 |
| MarkSent | Processing | Sent, дата отправки, очистка LastError |
| FailAttempt, временная ошибка, есть попытки | Processing | Pending, LastError |
| FailAttempt, постоянная ошибка или лимит | Processing | Failed, LastError |

Временная ошибка возвращает Pending: уведомлению ещё предстоит повторная публикация.
Pending пока не запускает никаких фоновых действий. Планирование задержки, запись
Outbox и публикацию реализуем отдельно. MaxAttempts включает первоначальную попытку.

Повторный BeginAttempt на том же объекте запрещён и не увеличивает счётчик.
Это локальная защита правил модели, а не распределённая идемпотентность:
несколько Worker потребуют атомарного захвата задачи в БД.

Sent и Failed пока конечные состояния. Ручной retry из Failed добавим отдельной
операцией с правилами нового цикла попыток и сохранением истории.
История DeliveryAttempts и Idempotency-Key будут реализованы вместе с хранением.

## Время и ошибки

Методы принимают DateTimeOffset: время с часовым смещением, которое сохраняется
в UTC. Его передаёт вызывающий компонент, а не клиент HTTP API. Это позволяет
тестам использовать фиксированное время без ожиданий и обращения к часам машины.

ArgumentException означает некорректные данные. InvalidOperationException —
запрещённую операцию в текущем состоянии. Позже HTTP-слой сопоставит ожидаемые
ошибки с подходящими кодами ответа.

Модель не отправляет email и не обращается к БД. Её обязанность — данные и правила.
Интерфейс провайдера появится вместе с реализацией отправки.

## Проверка и практика

NotificationTests проверяет успешную отправку, временные и постоянные ошибки,
исчерпание лимита, запрещённые переходы и валидацию данных.
Существующие ApiTests продолжают проверять HTTP-конвейер.

1. Проследите путь уведомления при двух временных ошибках и успешной третьей попытке.
2. Объясните, почему AttemptsCount увеличивается в BeginAttempt, а не MarkQueued.
3. Найдите тест, который запрещает повторную обработку Sent.
4. Добавьте тест, проверяющий UpdatedAt после временной ошибки.

Следующий компонент: контракт HTTP-запроса и PostgreSQL-хранение. Новые зависимости
и инфраструктуру устанавливает пользователь по инструкции; автоматической загрузки нет.
